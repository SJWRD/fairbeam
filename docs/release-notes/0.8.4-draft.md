# Fairbeam 0.8.4 — stabilization notes draft

This record documents the changes and review scope used to prepare Fairbeam 0.8.4. It does not
announce release availability. The release-preparation branch sets the application version to
0.8.4; combined validation, review and tagging remain pending. Changes marked as pending below
are not yet included on main. Final published notes must describe only the release tag.

## Changes already on main

- Preserve saved-design and result ownership across first Save, Save As, model switches and
  failed preview validation. Missing-workspace recovery offers Try again, Use the default
  workspace and Choose another folder. A missing saved custom workspace folder is not
  recreated automatically; the default workspace and missing subfolders can still be seeded.
  Damaged runtimes offer an explicit Repair action.
- Keep viewport dimensions, report tables and drawing figures consistent for mm, cm and m
  models. Preserve completed convergence outcomes when Stop races with completion. Stop also
  prevents the next, finer density from starting, including when the study file cannot be
  written. Keep integer sweep values consistent with preview.
- Improve English and Turkish feedback for native file operations, queue actions, exports,
  numerical inputs and reference-data drops. Drops outside the visible Results/Examples
  comparison no longer import into hidden reference data. Recognized macro drops (`.bas`,
  `.mcs` and macro-like `.txt`) and PCB drops (`.dxf`, `.gbr`, `.gerber`, `.drl`) receive
  guidance to their import tools; other unsupported types report an error. Results continues
  to parse measurement data before classifying text as a macro.
- Retain the focused Compare checkbox when the result index refreshes. Space continues to
  toggle that row, and Escape returns focus to the Compare control.
- Show endpoint contact feedback and touching-primitive highlights. Lumped R/L/C elements use
  green rings for contact, red for no contact and gray for undetermined geometry. Discrete
  ports show only red rings for endpoints with no contact; no ring can mean contact or an
  undetermined result. Geometry that fails to resolve can make contact undetermined. This is
  a placement aid, not proof of final mesh connectivity or a validated simulation connection.
- Close and Quit now ask before canceling running or queued simulations for any model,
  including sweep, optimization and research runs. In 0.8.3, Close/Quit never mentioned run
  cancellation, even when an unsaved-work question appeared. A failed run-status check also asks.
  macOS Dock Quit and logout/restart requests now share the run, unsaved-draft and pending-Save
  questions; real logout/restart remains untested natively.
- The first failed close-handler reply cancels the current decision; the next explicit Quit/Close
  probes again. A recent repeated script error can use the exit fallback, while valid replies
  clear that opportunity. Update consent remains available and never uses the error fallback.
- Guard native New/Open/Start/Design/Examples/Open Recent while a modal owns the interaction.
  Correct macOS native menu conventions and application metadata, improve initial Simulation
  settings focus, and retain Results with the minimized ribbon.
- Correct figure-export numbers, notes and dash patterns. Exported legends keep wrapped
  lines; raw names, combining marks included, are kept as-is.
- Toolbar CSV downloads now begin with a UTF-8 BOM so Excel recognizes headers containing
  Ω and ∠. Package and clipboard data remain BOM-free, with decimal values preserved. Scripts
  reading toolbar CSVs should strip U+FEFF, for example with Python's `utf-8-sig` encoding.
- Move optional GPU support installation from the startup screen to Settings, with progress,
  failure reasons and the log path. Runtime updates at startup show step progress. Bundled
  runtime installation checks the pinned macOS minimum version; older systems get an
  explanation and the option to use an existing openEMS Python installation.
- Align English and Turkish guidance with current project, solver and ribbon workflows.
  When the run server is unavailable, explain how to restart Fairbeam; this does not add
  automatic server recovery. In-app Elmer help opens the published English or Turkish guide.
- Avoid repeatedly transferring historical result arrays during ordinary/research list
  polling, while keeping full selected-result detail available and preserving cancellation.
- Record completed-result provenance even while a long Save holds the workspace lock.
  Publish complete records exclusively and preserve conflict and linked-directory checks.
- Bind server startup attempts to their generation, child and ready state. Superseded workers
  cannot replace or stop the current server; updater interruption remains recoverable. The
  remaining macOS/Unix exit-during-spawn timing window is described below.
- Preserve failed and recovered browser-attempt evidence, plus prelaunch and same-launch
  diagnostics in the scenario runner and CI. These are test-infrastructure changes; they do
  not establish a fix for #251.
- Add five opt-in research comparison fixtures for multihole, branchline, multisection
  stripline and ring-hybrid couplers, and a loaded TEM cell. Their 101 default unit tests do
  not run FDTD or establish solver qualification; field solves remain explicit opt-in work.
- Repair standalone checks and document their prerequisites. Add citation metadata and the
  source-archive process, including the corrected published author and affiliation forms.
